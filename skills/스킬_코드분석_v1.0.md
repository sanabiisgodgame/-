# 스킬_코드분석_v1.0.md
> 최초 작성: 2026-04-26  
> 작업 유형: 코딩 작업 전 “심층 분석 문서” 작성(단일 파일/프로젝트 포함)

---

## 목표
- 새 코딩 파일을 받으면, 수정/추가 전에 **구조를 완전히 파악**한다.
- “전문가용(정확/체계)” + “초보용(쉽게/교육)” 두 관점으로 정리해, 사용자가 피드백을 주기 쉬운 상태를 만든다.
- 분석 중 발견한 문제/개선점은 즉시 고치지 않고 **개선 후보**로 분리해, 별도 플랜+승인 후 진행한다.

---

## 기본 원칙
1. **분석 → 플랜 → 승인 → 실행** 순서 고정 (예외 없음)
2. 분석 문서는 `*_분석.md`로 만들고, 다음 수정 때도 계속 갱신한다.
3. 전문용어는 괄호로 쉬운 설명을 추가한다.
4. “추측”은 추측이라고 표기한다(그럴듯한 꾸며내기 금지).

---

## 준비(기준본 고정)
- 새 파일이 들어오면, 우선 프로젝트 내부에 기준본으로 복사한다.
  - 예: `games\해초농장_v8.5.html`
- 이후 분석/수정은 **프로젝트 기준본만** 대상으로 한다(Downloads 등 외부 경로 혼용 금지).

---

## 분석 산출물(필수)
### 1) 전문가용(깊이 분석)
반드시 포함:
- 파일 메타: 용량/줄 수/버전 표기/저장 키(localStorage key)/외부 의존성
- 코드 지도: 큰 섹션 맵 + 핵심 라인 앵커
- UI 맵: 화면 레이아웃(데스크톱/모바일), 모달/오버레이/토스트 구조
- 데이터 정의: 상수/테이블(확률/가격/업그레이드/아이템 등)
- 상태(State) 표: 핵심 객체/필드가 “어디서 변경/어디서 읽힘”인지
- 실행 흐름: 초기화 → 루프 → 로직 → 렌더 → 저장 (mermaid 다이어그램 포함)
- 시스템별 딥다이브: 오디오/이벤트/저장/성능 최적화 포인트 등
- 수정 안전지대/위험지대: “어디를 건드리면 위험한지”를 명시
- 개선 후보 목록: 후속 플랜용(지금 수정 금지)

### 2) 초보자용(쉽게 설명 + 교육)
반드시 포함:
- 비유로 설명: 상태/루프/렌더/저장 개념
- 용어 사전(전문용어→쉬운 설명)
- “어디를 바꾸면 무엇이 바뀌나” 10줄 요약
- 다음 확인 질문: 사용자가 목표를 선택하기 쉽게 질문 3~7개

권장 파일명:
- `해초농장_분석.md` 처럼 “프로젝트/콘텐츠 이름+_분석”

---

## 분석 순서(권장)
1. **HTML**: 화면 구성요소(id)와 동적 생성 요소(규칙) 구분
2. **CSS**: 레이아웃(그리드/반응형), 핵심 클래스(상태별) 확인
3. **JS**
   - 상수/데이터 테이블 먼저 파악
   - 상태 객체(예: `S`) 필드 목록화
   - 루프/렌더/저장/이벤트 순으로 흐름 파악
4. 마지막에 “안전지대/위험지대/개선 후보/질문” 작성

---

## 자주 하는 실수(금지)
- 분석 문서 없이 바로 수정하기
- 분석 중 발견한 버그를 승인 없이 즉시 고치기
- 동적 생성 id 규칙을 무시하고 UI id를 바꾸기(즉시 깨짐)
- 저장 스키마 변경을 가볍게 보기(기존 저장 호환 깨짐)
